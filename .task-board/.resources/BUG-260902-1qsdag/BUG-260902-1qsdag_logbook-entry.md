### 1933 — A failure to read is not a mismatch, and the store was moving data on the difference

- FINDING: `ObjectStore.PutBlob` treated any non-nil `inspectExisting` error other than `ErrUnsafeOwnership` as authority to quarantine the EXISTING immutable object. `inspectExisting` returned raw `os.Lstat`, `os.Open`, `io.Copy` and `Close` errors, so at the decision point an EMFILE or a transient I/O fault was byte-for-byte indistinguishable from a proven hash mismatch. A flaky read could permanently sideline a valid object out of the immutable namespace. SPEC.md:819-820 authorizes quarantine for a hash mismatch or representation disagreement only; a read that did not complete proves neither.
- ROOT CAUSE of why the existing suite stayed green: every quarantine test supplied a real corrupt occupant, so the mismatch branch was well covered and the read-failure branch was unreachable from any fixture. The two faults shared one code path, and no test could tell them apart because no test could produce the second one. This is the absence-vs-failure distinction landing on the side that moves data.
- DECISION: `inspectExisting` now returns an `existingVerdict` (`existingAbsent` / `existingMatches` / `existingDisagrees` / `existingUnsafe` / `existingUnreadable`) and classifies only what it PROVED; it makes no move decision. `resolveExistingConflict` is the single owner of what gets moved, shared by the pre-install and the raced create-new inspection so the two sites cannot drift on the one decision §3.2 constrains — the original defect was exactly a decision duplicated at two sites.
- DECISION, the seam that was not optional: `storeOperations` gained an injectable `openForRead`. A transient read failure on an owner-only 0600 regular file CANNOT be produced from the filesystem alone — every on-disk fault that makes `os.Open` fail also changes the mode or type, which `verifyOwnerFileInfo` rejects earlier as an ownership refusal. chmod 0 does not reach the reader; it reaches the ownership gate. Without the seam this classification could only be argued.
- EVIDENCE: 2 mutants, both killed. The delete-mutant (drop the `existingUnreadable` guard) reproduces the original defect verbatim, with `ExistingQuarantinePath` populated in the failure output. The narrowing mutant (`existingDisagrees` on a read failure) is the one that matters, because a delete-only mutant would only have proven the guard exists. `BUG-260902-1qsdag_mutant-evidence.log`.
- FINDING: the projection path already had this right — `scanAuthoritativeBlobs` routes open/read/close failures through `sourceFailure` and refuses. The two paths are now asserted to agree rather than assumed to: one test drives `PutBlob` and `openProjection` over the same data root with the same class of fault and requires that neither reports a mismatch sentinel, the object stays byte-identical, and the quarantine root stays empty.

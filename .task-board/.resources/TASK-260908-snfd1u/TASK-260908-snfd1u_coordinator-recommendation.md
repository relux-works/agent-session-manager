# Coordinator recommendation \u2014 proposed, not approved

User requested elegant, stable, safe solutions. The researcher comparison is retained as background. This recommendation changes its default selection where operational complexity matters. No existing product implementation, protocol pin or acceptance has changed.

## D1: Source-qualified selection

Recommend source-index semantics, with session UUID as durable identity. Keep bare NAME and UUID behavior exactly as pinned. Explicit id:UUID bypasses name precedence. Canonical qualified forms are NAME@local, NAME@peer:ALIAS and NAME@id:HOST_UUID, with id:SESSION_UUID allowed as the key. Split at the FIRST @ only: NAME and id:UUID cannot contain @, while the complete peer: suffix is a literal existing configured alias (including further @, colons and Unicode). CLI receives one argument, quoted by the ordinary shell when needed. This avoids inventing percent-encoding/canonical URL rules for display aliases. No normalization or case-folding of host aliases is added. No fallback from an explicit source; unknown source, failed read and genuinely empty successful index remain distinct. Resolve to session UUID once; bind record/configuration/lease facts into a plan and revalidate before action. Source is never destination or proof of current ownership. Proposed examples: ax status build@peer:workstation; ax status "build@peer:Work Laptop"; ax status build@local; ax status id:<session-uuid>.

## D2: Standard mutually authenticated host channel

For the general cross-platform product, recommend TLS1.3 mutual authentication over the existing SSH byte stream. Retain SSH authentication and server verification; add dedicated AX host credentials, explicitly enrolled trust and a unique verified certificate/public-key-to-host-UUID mapping. Derive peer identity from the verified TLS connection, then require RPC hello.host_id equality before application dispatch. Never infer the identity from hello, launcher argv or an env variable. Use maintained crypto/tls authentication/record protection, not an ad hoc signed-nonce exchange; no 0-RTT, unauthenticated fallback or session resumption in the initial profile. No application frame is admitted until mutual TLS authentication completes. Preserve limits/deadlines on handshake and framing.

This choice trades a documented credential lifecycle and versioned transport/configuration change for a uniform identity model across OpenSSH and native Tailscale SSH; it avoids a per-sender OS-account matrix and platform-specific trusted IPC admission service as the default. Server-enforced restricted SSH identities remain a viable alternative deployment profile, not equivalent without those OS protections. The current raw line-JSON invocation cannot silently become TLS: define a distinct explicitly selected launch/transport version and migration, preserving old closed RPC versions where explicitly supported and refusing downgrade for peers requiring strong identity. Do not hide auth in extensions or claim this is already allowed by the pinned specification.

Enrollment verifies host UUID plus public credential fingerprint out of band; no auto-trust on first hello. Keep private keys machine-local, excluded from snapshots. Trust-store changes are explicit and atomic. Rotation retains UUID with bounded old/new credential overlap; never map one credential to multiple hosts. Revocation removes admission and closes existing streams; each mutation rechecks current authorization generation. Validate certificates and intended role under the selected standard trust profile; do not turn TLS verification off. The exact certificate issuance/trust representation must be frozen in the specification before implementation. No online CA service is assumed by this proposal.

TLS authenticates possession of an enrolled private key, not physical-machine uniqueness. A copied key or compromised target account capable of reading/replacing AX state/credentials is outside this identity assurance; arbitrary remote shell access cannot be made safe merely by adding a wrapper. Do not claim to solve local-account compromise.

Primary sources: TLS1.3 authentication and protected records https://www.rfc-editor.org/rfc/rfc8446.html#section-4.4 ; maintained Go TLS API https://pkg.go.dev/crypto/tls ; OpenSSH forced command/restrictions https://man.openbsd.org/sshd.8 ; native Tailscale SSH uses its own authentication/server https://tailscale.com/docs/features/tailscale-ssh . These establish building blocks, not an executed AX deployment proof.

## Evidence bounds

- Repeated closing observations detect persistent source changes, not a change
  that occurs and is completely reverted between reads. The held terminal and
  provider quiescence is the protection during the interval.
- Git's external execution and host filesystem are trusted; arbitrary filter
  sandboxing and cross-platform runtime equivalence are not proved here.
- Arbitrary Git destination materialization, checkpoint publication, doctor
  capability advertising, group-history selection/conflict resolution, and a
  live-session capture that returns to active are outside this leaf's contract.
- OS-specific maximum path depth/bytes and scale behavior above the stated
  generated boundaries remain bounds, not inferred guarantees.


## Rev7 inherited synchronization-property audit

This audit responds to the whole-Story reviewer product-property checks. The Story rework does not modify `internal/merkleinventory`; the source and tests are byte-identical to `origin/main`. `DurableIndex.SyncFrom` is covered by `TestDurableSyncGeneratedPerturbationProduct`: the configured suite generates N=1..3; nested generated selectors extend the finite fixture to N=1..6. For N<=5 it enumerates every permutation; N=6 uses 34 deterministic permutations. The generated dimensions are both clock-skew directions, duplicate replay absent/present, no gap or one delayed object selected cyclically, every proper peer subset, repeated valid sync passes 1..3, and every feasible conflict target × conflict round 1..3. The object fixture is structurally six entries: one repository record, two competing lease records, one event, one Tombstone, and one Tombstone Acknowledgement; reference namespaces also include blob.

The oracle independently orders IDs, computes Merkle roots recursively, compares lease winners by the normative epoch/lease-ID tuple, and checks durable byte snapshots. Generated size and rounds have ranges; the six-entry fixture caps these cases and does not establish behavior for arbitrary object counts or more than three sync rounds. Production `SyncFrom` iterates exact identity slices and requests in 4096-object chunks, but scale above the fixture remains unmeasured.

Reviewer-requested solo narrowing plants were applied through the copied existing `internal/merkleinventory/mutations.py` harness in two independent passes. Each test ran alone and exited 1 with its named test failing; each harness invocation exited 0. The duplicate-drop plant first survived `TestDurableSyncDuplicateDeliveryIsByteIdentical`: that test only compares after its initial delivery. Retargeting the same plant to the existing crash/reopen idempotency test (`TestDurableJSONAddIsIdempotentAcrossCrashRestartByNamespace`) killed it in three independent runs, because reopening reveals the missing persisted object.
